# Цаг бүртгэл ба ирцийн систем (Time Registration & Employee Attendance)

Ажилтны **ирсэн цаг** (Ирсэн цаг) болон **явсан цаг** (Явсан цаг)-ыг бүртгэж, ажлын
стандарт хуваарьтай (**09:00 – 19:00**, үдийн завсарлага **13:00 – 14:00**) харьцуулан
**Хоцролт** (late arrival) ба **Эрт явалт** (early departure)-ыг минутаар автоматаар тооцоолох систем.

* Бүх интерфэйс, товч, форм, анхааруулга, тайлан — **монгол хэл дээр**
* GPS **гео хаалт** — ажлын байранд байхгүй бол бүртгэл хийхгүй
* **Ажил эхлэх/дуусах бүрд ЗУРАГ заавал** — гео хаалт дангаараа хангалтгүй (v3)
* Ажилтан бүр **өөрийн бодит цагийн цалин**, цаг, өдрөө харна (v3)
* **Чөлөөг ажилтан аппаас хүсэж, админ мэдэгдлээс батална**; зөвхөн **3 төлөв**:
  чөлөө / ирээгүй / хэвийн (v4)
* **Цагийн тариф (v4.1)**: өдрийн цалинг ажлын бүтэн цагт хуваана — 150 000₮/өдөр →
  **15 000₮/ц** (10ц, үдийн завсарлага орсон); 19:00–03:00 цагт **18 750₮/ц** (8ц)
* **AI агентад** зориулсан REST API + CLI + OpenAPI 3.0 тодорхойлолт
* Гадаад сан **шаардахгүй** (Python 3.10+ stdlib), SQLite мэдээллийн сан
* Excel (.xlsx) / CSV экспорт — цалингийн тооцоонд бэлэн

## 2. Үндсэн логик (Core logic)

```
Ажлын хуваарь (ж: 09:00–18:00, хөнгөлөлт 0 мин)
   │
   ├── Ирсэн цаг > 09:00 + хөнгөлөлт  →  ХОЦРОЛТ = ирсэн − эхлэх цаг (минут)
   ├── Явсан цаг < 18:00              →  ЭРТ ЯВСАН = дуусах цаг − явсан цаг (минут)
   │
   ├── Ажилласан минут   = явсан − ирсэн (− үдийн завсарлага)
   ├── Хасагдсан минут   = ХОЦРОЛТ + ЭРТ ЯВСАН
   └── Төлбөртэй минут   = Ажилласан минут − Хасагдсан минут
```

* Ажлын бус өдөр (Бямба/Ням, тохиргоогоор) хоцролт/эрт явалт тооцохгүй.
* Хөнгөлөх хугацаа (grace period) тохируулж болно — ж: 5 мин хөнгөлөлттэй бол
  09:05 хүртэл ирсэн нь хоцролтод тооцогдохгүй.
* Шөнийн ээлж (ж: 22:00–06:00) дэмжигдэнэ.
* **Тохиргоо өөрчлөгдвөл** (ажлын цаг, хөнгөлөлт, үдийн завсарлага, ажлын өдрүүд)
  бүх бүртгэл автоматаар **дахин тооцоологдоно** (аудит бүртгэлд хадгална).

## 4. Удирдлагын самбар

* **Шууд самбар** — хэн ажиллаж байна, хэн хоцорсон (улаан), хэн эрт явсан (шар),
  хэн ирээгүй (бараан улаан). 15 секунд тутам автомат шинэчлэлт.
* **Автомат тэмдэглэл** — хуваарьтай харьцуулж **Хоцорсон / Эрт явсан** гэж
  шошголж, минутыг хүснэгтэд харуулна; хоцролт/эрт явалтын минут автоматаар хасагдана.
* **Сарын тайлан** — Ажилтны нэр · Нийт ажилласан цаг · Нийт хоцорсон тоо ·
  Нийт эрт явсан тоо · **Хасагдсан нийт минут** · Төлбөртэй цаг.
  `Excel (.xlsx)`, `CSV`, `Хэвлэх / PDF` товчтой.
* **Хүснэгт (heatmap)** — ажилтан × өдөр матриц, өнгөөр ялгасан.
* **Ажилтнууд** — бүртгэх/засах, ПИН код, идэвхтэй/идэвхгүй.
* **Гео хаалт** — ажлын байрны координат, радиус, зөрчлийн бүртгэл.
* **Тохиргоо** — ажлын цаг, хөнгөлөлт, үдийн завсарлага, ажлын өдрүүд, байгууллагын
  нэр, цагийн бүс, админ нэвтрэх нэр/нууц үг, аудитын бүртгэл.
* **AI агент** — API түлхүүр үүсгэх/идэвхгүй болгох, агентын харагдац (vision).

### Демо өгөгдөл
Амралтын өдөр эсвэл бүртгэл хоосон үед самбар дээр
**«🧪 Туршилтын (демо) өгөгдөл үүсгэх»** товч гарч ирнэ. Товч дарахад хоцорсон,
эрт явсан, ажиллаж байгаа, ирээгүй гэсэн бүх төлөв бүхий туршилтын бүртгэл
үүсч, самбар хэрхэн ажилладагийг шууд харуулна. `🗑️ Демо өгөгдлийг устгах`
товчоор цэвэрлэнэ (бодит бүртгэлд нөлөөлөхгүй).

## 5. Гео хаалт (Geofencing)

1. Ажилтны GPS координатыг `navigator.geolocation`-аар авна.
2. Ажлын байрны координаттай **Хаверсины томьёогоор** зайг тооцоолно.
3. Зай > радиус (ж: 300 м) бол бүртгэлийг **блоклоно**:

> **«Та ажлын байрандаа байхгүй байна. Бүртгэл амжилтгүй.»**

Блоклогдсон оролдлого бүр `clock_in_blocked` / `clock_out_blocked` болж
**аудитын бүртгэлд** хадгалагдаж, *Гео хаалт → Хязгаарлалтын бүртгэл* хэсэгт харагдана.

**Туршилтийн горим:** GPS байхгүй орчинд (ж: Preview, desktop) `demo_mode = 1` үед
хэрэглэгч зөвшөөрсний дараа демо координатаар бүртгэл хийгдэж, бүртгэлд
`[ДЕМО ГОРИМ]` гэж тэмдэглэгдэнэ. Бодит ажиллагаанд `demo_mode = 0` тохируулна уу.

## 7. AI агентын холболт

### 7.1 OpenAPI тодорхойлолт
```
GET /openapi.json      # OpenAPI 3.0 (54 зам, монгол тайлбартай)
```
Пайплайнаа (LangChain, OpenAI tools, n8n, Make, Dify …) шууд оруулж болно.

### 7.2 CLI (cron / автоматжуулалт)
```bash
export ATTENDANCE_URL=http://localhost:8000
export ATTENDANCE_API_KEY=att_demo_agent_key_2026

python3 agent_cli.py status                     # ирцийн шууд самбар
python3 agent_cli.py vision --date 2026-10-04   # LLM-д өгөх текстэн төлөв
python3 agent_cli.py who --code EMP005          # нэг ажилтны төлөв
python3 agent_cli.py clock-in  --code EMP005 --lat 47.9184 --lng 106.9177
python3 agent_cli.py clock-out --code EMP005 --lat 47.9184 --lng 106.9177
python3 agent_cli.py late-check                 # cron: */30 * * * 1-5
python3 agent_cli.py report --month 2026-09
python3 agent_cli.py export --month 2026-09 --out timesheet.xlsx
python3 agent_cli.py geofence --lat 47.92 --lng 106.92
```

### 7.3 REST жишээ
```bash
# Төлөвийг унших
curl -H "X-API-Key: $KEY" http://localhost:8000/api/agent/vision

# Ажилтны өмнөөс бүртгэл хийх (гео хаалт шалгана)
curl -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"employee_code":"EMP001","latitude":47.9184,"longitude":106.9177}' \
  http://localhost:8000/api/agent/clock-in

# Сарын тайлан
curl -H "X-API-Key: $KEY" "http://localhost:8000/api/agent/monthly-report?month=2026-09"
```

### 7.4 Агентад өгөх жишээ системийн заавар (prompt)
> Чи «Цаг бүртгэлийн систем»-ийн туслах. Хэрэглэгч «хэн хоцорсон бэ?» гэвэл
> `GET /api/agent/status` дуудаж, `late_minutes > 0` бүхий ажилтнуудыг жагсаа.
> «Сарын тайлан гарга» гэвэл `GET /api/agent/monthly-report?month=YYYY-MM`
> дуудаж, Ажилтны нэр, Нийт ажилласан цаг, Нийт хоцорсон тоо, Хасагдсан нийт минут-ыг
> хүснэгтээр харуул. Бүртгэл хийхийн өмнө заавал `latitude`/`longitude` авч,
> гео хаалтад хаагдвал «Та ажлын байрандаа байхгүй байна. Бүртгэл амжилтгүй.» гэж хэл.

## 9. Тохиргоо (Settings)

Тохиргоог UI-аас (**Тохиргоо** таб) эсвэл `PUT /api/admin/settings`-ээр хийнэ.
Эсвэл анхны утгыг `core.py`-ийн `DEFAULT_SETTINGS`-д өөрчилнө үү. Хадгалагдах сан:

| Түлхүүр | Утга |
|---|---|
| `company_name` | Байгууллагын нэр |
| `timezone` | `Asia/Ulaanbaatar` |
| `schedule_start` / `schedule_end` | `09:00` / `19:00` |
| `grace_minutes` | Хөнгөлөх хугацаа (мин) |
| `lunch_start` / `lunch_end` / `lunch_paid` | Үдийн завсарлага `13:00`–`14:00`, цалингүй (`0`) |
| `require_photo` | Бүртгэл бүрд зураг заавал эсэх (`1` = тийм) |
| `photo_max_kb` | Зургийн дээд хэмжээ (KB, анхдагч 1500) |
| `notify_start` / `notify_end` | Ажил эхлэх/дуусах сануулга илгээх эсэх |
| `notify_missed_minutes` | Бүртгээгүй бол хэдэн минутын дараа сануулах |
| `auto_absent` | Бүртгэлгүй өдрийг автоматаар «тасарсан» болгох |
| `auto_approve_extra` | Нэмэлт ажлын сегментийг автоматаар батлах |
| `workdays` | `1,2,3,4,5` (1=Даваа … 7=Ням) |
| `geofence_enabled` / `geofence_lat` / `geofence_lng` / `geofence_radius_m` | Гео хаалт |
| `demo_mode` | GPS-гүй туршилтын горим (0/1) |
| `admin_user` / `admin_password` | Удирдлагын нэвтрэх эрх |

## 12. Аюулгүй байдал ба анхаарах зүйл

* Анхны нууц үг (`admin/admin123`, ажилтны ПИН `1234`)-ийг **заавал солино уу**.
* API түлхүүр нь бүрэн эрхтэй — зөвхөн сервер талд хадгална (браузерын кодод бичихгүй).
* Сесс 12 цагийн дараа дуусна; бүх бүртгэл/засвар **аудитын лог**-т үлдэнэ.
* SQLite нь нэг серверт тохиромжтой; олон мянган ажилтантай үед PostgreSQL руу
  шилжүүлэхийг зөвлөнө (`core.py`-ийн SQL нь стандарт).
* Бүх цаг **серверийн цагаар** (тохируулсан цагийн бүсээр) бүртгэгдэнэ — ажилтны
  төхөөрөмжийн цагт найдахгүй.

## 14. Барилгын бригадын цалингийн модуль (v2)

Жижиг барилгын бригад： ажилтан бүр **өөр өдрийн цалин**, **өөр ажлын байр**тай,
шөнийн ээлж болон чөлөөг гараар тохируулдаг. Бүх тооцоо монгол хэл дээр, өнгөний кодтой.

### 14.1 Ажилтан тус бүрийн өдрийн цалин
* Ажилтны бүртгэлд `daily_rate` (₮/өдөр), `night_role` (`guard` = хамгаалалт,
  `worker` = ажилчин), `site_id` (ажлын байр) хадгална.
* Админ **Цалин** хуудсан дээр хүснэгтээс шууд өдрийн цалинг засна (эсвэл
  «Цалин» модальд үүрэг, ажлын байрыг хамт өөрчилнө). Хадмагц бүх бүртгэл
  дахин тооцоологдоно.
* Шинэ ажилтан нэмэхэд `default_daily_rate` (анхдагч 80 000₮) хэрэглэгдэнэ.

### 14.2 Цалингийн тооцооны томьёо
```
Ээлжийн цонх  = өдөр 09:00–19:00 = 600 мин (10ц, үдийн завсарлага ОРСОН)
                шөнө 19:00–03:00 = 480 мин (8ц)
Хөдөлмөрийн өдөр (day_credit) = ажилласан минут ÷ ээлжийн цонх   (дээд хязгаар 1.0)
Үндсэн цалин  = Өдрийн цалин × Хөдөлмөрийн өдөр × Ээлжийн коэффициент
Цагийн тариф  = Өдрийн цалин ÷ ээлжийн бүтэн цаг
                өдөр: 150 000₮ ÷ 10ц = 15 000₮/ц
                шөнө 19:00–03:00: 150 000₮ ÷ 8ц = 18 750₮/ц (хамгаалалт 50% → 9 375₮/ц)
Нэмэлт цаг    = (өдрийн минут × 15 000₮/ц) + (шөнийн минут × 18 750₮/ц × коэф.)
                × overtime_multiplier   ← сегментийн цаг 19:00–03:00-д орсон эсэхээр
Чөлөөний цалин = Цагийн тариф × Цалинтай чөлөөний цаг (бүтэн өдөр = 10ц = 1 өдрийн цалин)
Торгууль      = (Үндсэн + Нэмэлт + Чөлөө) × 10%   ← 3 хоног дараалан тасарвал
ОЛГОХ ЦАЛИН  = Үндсэн + Нэмэлт + Чөлөө − Торгууль
```
* **Өдрийн ээлж** (09:00–19:00): коэффициент 1.0. Үдийн завсарлага 13:00–14:00
  нь **цалинтай** (`lunch_paid=1`) тул цагийн тариф нь өдрийн цалинг **10 цагт**
  хуваана (150 000₮ → 15 000₮/ц), бүтэн өдөр = яг өдрийн цалин. Хоцролт/эрт явалт
  нь хөдөлмөрийн өдрийг бууруулна (минут тутам, 150 000₮-ийн жишээгээр 250₮/мин).
* **Шөнийн ээлж** (19:00–03:00): цагийн цонх 8 цаг бөгөөд **нэг бүтэн ажлын өдөрт**
  тооцогдоно. Цалингийн коэффициент: **хамгаалалт 50%**, **ажилчин 100%**.
  19:00-ийн дараах **нэмэлт цаг** мөн энэ тарифаар: 150 000₮ ÷ 8ц = **18 750₮/ц**.
  Ажилтан 19:00-ийн 90 минутын дотор ирвэл шөнийн ээлжид автоматаар бүртгэгдэнэ.
  Шөнө дунд дараа өдөр буусан ч бүртгэл нь эхний өдөрт хамаарна.
* **Чөлөө** (цагаар эсвэл бүтэн өдрөөр): **зөвхөн админаар БАТЛАГДСАН** чөлөө нь
  тухайн өдөр/цагийн тасалдлыг нөхөж, хасалт үүсэхгүй. Хүлээгдэж буй (pending)
  хүсэлт нь тасалдлыг **нөхөхгүй** (v4). Цалинтай эсэхийг хүсэлт тус бүрээр
  админ шийднэ (`paid=0/1`) — төрлөөр ангилах `paid_leave_kinds` v4-д ашиглагдахгүй.
* **Тасралтын торгууль**: ажилтан зөвшөөрөлгүй (чөлөөгүй) **3 ажлын өдөр
  дараалан** ирээгүй бол тухайн сарын цалингаас **10%** хасна. Хугацаа,
  хувийг Тохиргоо → Цалингийн дүрэм-ээс өөрчилж болно.
* **Нэмэлт цаг**: (а) админ ажилтанд гараар нэмнэ (Цалин → «+» товч), (б) ажилтан
  өөрөө «Нэмэлт ажил эхлэх/дуусгах» товчоор **зурагтай** бүртгэнэ (v3, §15.4).
  Цагийн тариф нь сегментийн цагаар тодорхойлогдоно: 19:00-ийн өмнөх минут
  15 000₮/ц, 19:00–03:00-ийн минут 18 750₮/ц (150 000₮ өдрийн цалингийн жишээгээр);
  шөнийн ажилд ээлжийн коэффициент (хамгаалалт 50% / ажилчин 100%) ба
  `overtime_multiplier` үржигдэнэ. Аудит логт бичигдэнэ.
* **Торгуулийн суурь** = Үндсэн + Нэмэлт + Цалинтай чөлөө (торгуулийн өмнөх дүн).
  `gross` талбар нь яг энэ дүн, `total` нь торгууль хасагдсаны дараах олгох цалин.

### 14.3 Ажлын байр (талбай) — ажилтан бүрд өөр байршил
* **Ажлын байр** хуудсанд талбай нэмнэ: нэр, хаяг, өргөрөг/уртраг, радиус (м).
  (v4.2: байршлыг **Google Maps-аас** сонгох — §17-г үзнэ үү.)
* Ажилтанд хүснэгтээс шууд талбай онооно. Оноогоогүй бол үндсэн гео хаалт
  (`geofence_lat/lng/radius_m`) үйлчилнэ.
* Бүртгэлийн үед ажилтны **өөрийн талбайн** хүрээ шалгагдана; гаднаас
  бүртгүүлэх оролдлого «Та ажлын байрандаа байхгүй байна. Бүртгэл амжилтгүй.»
  гэсэн мессежтэй хаагдаж, гео логт үлдэнэ.
* Демо цэгүүд: Төв оффис (Сүхбаатарын талбай), Нисэх онгоцны буудал —
  шинэ терминал, Зайсан — орон сууцны цогцолбор, Шинэ Яармаг — агуулах.
* SPA нь `GET /api/geo/check`-ээр **нэвтэрсэн ажилтны өөрийн талбайг** шалгана
  (талбай оноосон бол түүний радиус; эс бөгөөс үндсэн гео хаалт). Админ
  `/api/admin/geofence-check?employee_id=N`-ээр тодорхой ажилтны хүрээг шалгаж болно.

### 14.4 Чөлөө (нэг төрөл)
* **Чөлөө** хуудсанд ажилтан, огноо, хэлбэр (бүтэн өдөр эсвэл цаг), **цалинтай эсэх**-ийг
  сонгоно (v4: төрлийн ангилал — амралт/өвчтэй — бүрэн хасагдаж, нэг л «чөлөө» үлдсэн).
* Цагаар: `14:00–18:00` = 4 цаг. Олон хоногийн: `2026-09-28 → 09-30` (ажлын өдрөөр тооцно).
* Бүтэн өдрийн чөлөө = тухайн үеийн ажлын өдрүүд × **10 цаг** (өдрийн цалинтай тэнцэнэ).
* Шөнийн ээлжид ч цагаар чөлөө олгож болно (ж: `19:00–23:00`).
* Ажилтан бүрийн сарын хураангуй (батлагдсан чөлөө, цалинтай цаг, хүлээгдэж буй,
  татгалзсан) хүснэгтээр харагдана.
* Нэг өдөрт хэд хэдэн чөлөө бүртгэгдсэн бол **давхцсан хугацааг нэг л удаа** тооцно.
* Ажилтны илгээсэн хүсэлтийн бүрэн урсгалыг **§16**-аас үзнэ үү.

## 15. Ажилтны данс — v3 (зураг, бодит цагийн цалин, мэдэгдэл)

Ажилтан бүр **өөрийн дансаар** нэвтэрч (EMP001…EMP012 / ПИН `1234`), зөвхөн өөрийн
цаг, өдөр, цалинг харна. Админ бүгдийг харна.

### 15.1 Ажил эхлэх/дуусах бүрд ЗУРАГ заавал
* Зөвхөн гео хаалтаар бүртгэх нь хангалтгүй (ажилтан хувцас солих өрөөнд сууж болно) —
  тиймээс **ажил эхлэх (Ирсэн) ба дуусах (Явсан) бүрд камераар зураг авна**.
* SPA: `getUserMedia` → canvas (≥720 px, JPEG q0.7) → base64 → сервер. Камер
  ажиллахгүй бол **файлаас сонгох** fallback (утасны камер ч ажиллана).
* Сервер: `require_photo=1` үед зураггүй хүсэлт **422 + `need_photo: true`** буцаана.
  Зураг нь `data/photos/YYYY-MM/<emp>_<ts>_<kind>.jpg` болж хадгалагдана
  (`kind`: `in`, `out`, `extra_in`, `extra_out`), дээд хэмжээ `photo_max_kb`.
* Түүх болон админы хүснэгтэд зураг thumbnail-аар харагдана; дарж томруулна.

### 15.2 Ажлын цаг ба цалингийн өдөр
* Ажлын цаг **09:00–19:00**; үдийн завсарлага **13:00–14:00** (**цалинтай**, v4.1).
* Нэг бүтэн ажлын өдөр = **600 минут (10 цаг, үдийн завсарлага орсон)**;
  цагийн тариф = **өдрийн цалин ÷ 10** (150 000₮ → 15 000₮/ц), шөнө 19:00–03:00 = ÷ 8 (18 750₮/ц).
* Ажлын цонхоос гадуур (цагнаас өмнө/хойш) цаг нь зөвхөн «нэмэлт ажил» сегментээр тооцогдоно.

### 15.3 Бодит цагийн цалин (30 секунд тутам шинэчлэгдэнэ)
`GET /api/employee/live`:
```
ХУРИМТЛАГДСАН ЦАЛИН   хуримтлал (минут тутам нэмэгдэнэ)
АЖИЛЛАСАН ЦАГ          хаагдсан цаг + өнөөдрийн минут
АЖЛЫН ӨДӨР             1 өдөр = 10 цаг (600 мин, үдийн завсарлага орсон)
Цагийн тариф           өдрийн цалин ÷ 10 (шөнө 19:00–03:00: өдрийн цалин ÷ 8)
Тасарсан               хоног (дараалал n/3 → 3 бол −10%)
```
Ажил дээр байх үед нээлттэй ээлж, нэмэлт ажлын цаг ч бодит цагаар тооцогдоно.

### 15.4 Нэмэлт ажил (илүү цаг) — мөн зурагтай
* Ажилтан «**Нэмэлт ажил эхлэх**» / «**Нэмэлт ажил дуусгах**» товчоор бүртгэнэ;
  аль аль нь **зураг заавал** (`extra_in` / `extra_out`).
* Сегмент бүр минут, статус (`open` → `closed` → `approved`), хоёр зурагтай.
  `auto_approve_extra=1` үед дуусгамагц автоматаар батлагдана; эс бөгөөс
  админ «Фото хяналт»-оос батална. Батлагдсан минут = нэмэлт цаг (цагийн тарифаар).
* Шөнийн ээлж (19:00–03:00) хэвээрээ: **хамгаалалт 50% / ажилчин 100%**, нэг бүтэн өдөр.

### 15.5 Мэдэгдэл ба тасарсан бүртгэл
* Ажил эхлэх/дуусах цагт сануулга илгээнэ (`notify_start`, `notify_end`);
  бүртгэл хийгээгүй бол `notify_missed_minutes` дараа сануулна.
* Бүртгэлгүй ажлын өдөр **тасарсан (absent)** болно (`auto_absent=1`);
  3 хоног дараалан тасарвал сарын цалингаас **−10%** (өмнөх дүрэм хэвээр).
* Хонхны товч дээр уншаагүй мэдэгдлийн тоо; `POST /api/admin/notifications/tick`
  нь scheduler-ийг гараар ажиллуулна (60 с тутам автоматаар ажиллана, dedupe-тай).

### 15.6 Нууцлал (ажилтан бусдыг харахгүй)
* `GET /api/employee/*` нь зөвхөн өөрийн мэдээлэл; админы endpoint-ууд ажилтанд **403**.
* `GET /api/photos?path=` — ажилтан зөвхөн **өөрийн** зургийг (файлын нэрээр шалгана),

## 16. Чөлөөний хүсэлт ба гурван төлөв — v4

> «чөлөө, ирээгүй, хэвийн — thats all we need… хэрэв ажилтан хэдэн цаг, нэг өдөр эсвэл
> хэдэн өдрийн чөлөө авахыг хүсвэл аппаас хүсэлт илгээж, админ мэдэгдлээр батална.
> Ажлаас мэдэгдэлгүй явсан эсвэл ирээгүй бол тэр өдөр/цаг нь ирээгүй гэж тооцогдоно.
> Тиймээс хэсэг бүрд мэдэгдэл авах нь чухал.»

### 16.1 Гурван төлөв (өөр сонголт байхгүй)
| Төлөв | Код | Өнгө | Хэзээ |
|---|---|---|---|
| **Чөлөө** | `leave` | цэнхэр `#1d4ed8` | Зөвхөн админаар **батлагдсан** чөлөө байгаа үед |
| **Ирээгүй** | `absent` | улаан `#b91c1c` | Ажилд ирээгүй, эсвэл ажлаас мэдэгдэлгүй явсан (өдөр, цаг) |
| **Хэвийн** | `normal` | ногоон `#15803d` | Хуваарийн дагуу бүтэн ажилласан (хоцролт/эрт явалт нөхөгдсөн) |

Туслах төлөв: **Ажиллаж байна** (`working`, цэнхэр-ногоон `#0f766e`) — ээлж яваа үед;
**Амралтын өдөр** (`off`, саарал) — хуваарьт ажлын бус өдөр.
Бүтэн өдрийн чөлөө = `leave`; хэсэгчилсэн чөлөө нь тухайн өдрийн хасалтыг минутаар нөхнө
(үлдсэн хэсэг нь «ирээгүй» болж болно — админ `absent_minutes_grace` босгоор тохируулна).

### 16.2 Урсгал ба мэдэгдэл (хэсэг бүрд)
```
Ажилтан (апп)                         Админ (мэдэгдэл)              Систем
──────────────                        ────────────────              ──────
«Чөлөө хүсэх» → огноо/цаг/шалтгаан
   │  POST /api/employee/leave-request
   ├──────────── pending ──────────▶  🔔 «ЧӨЛӨӨНИЙ ХҮСЭЛТ»
   │                                   scope=admin, dedupe=leave_req_{id}
   │                                   ├─ Батлах  → POST …/{id}/decide {approve:true, paid:false}
   │                                   ├─ Татгалзах → {approve:false}
   │◀── 🔔 «ЧӨЛӨӨНИЙ ХҮСЭЛТ БАТЛАГДЛАА / ТАТГАЛЗАГДЛАА» (ажилтанд)
   │
   ├─ цуцлах → POST /api/employee/leave-requests/{id}/cancel
   │                                   🔔 «ХҮСЭЛТ ЦУЦЛАГДЛАА» (админд, dedupe=leave_cancel_{id})
   │
   ⏰ 20 мин хүлээгдэж байгаа хүсэлт хэвээр → 🔔 сануулга (dedupe=leave_pend_sched_{id})
   ⏰ 19:00+10 мин болтол ирээгүй / цаг хэтэртэл хаагдаагүй →
      🔔 «АЖИЛД ИРЭЭГҮЙ» + «БҮРТГЭЛ ХААГДААГҮЙ» → админ ба ажилтан (dedupe=left:{date}:{eid})
```
* Батлагдаагүй (pending) хүсэлт нь **тасалдлыг нөхөхгүй** — цаг нь `absent` хэвээр байна.
* Батлагдсан чөлөө нь тухайн өдөр/цагийн `absent_minutes`-ийг бууруулж, `leave_minutes`
  болж хөрвөнө; цалин **тухайн хүсэлтийн `paid` утгаар** (0/1) тооцогдоно.
* Ажилтан ирэхгүй, эсвэл ажлаас мэдэгдэлгүй явбал тэр өдөр/цаг «ирээгүй» (absent) болно;
  **3 ажлын өдөр дараалан** ирээгүй бол сарын цалингаас **−10%** (v2 дүрэм хэвээр).

### 16.3 Ажлын байр ба өнгийн код
* **Шууд самбар** дээр мөр бүрд «Өдрийн төлөв» багана + тайлбар (legend),
  админ «Хүлээгдэж байгаа хүсэлт» картаас шууд Батлах/Татгалзах.
* Ажилтны самбарт «Миний чөлөө ба хүсэлт» карт: батлагдсан, хүлээгдэж буй, татгалзсан
  хүсэлтийн төлөв нь өнгөөр ялгагдана; «Чөлөө хүсэх» модалаас шууд илгээнэ.
* Мэдэгдлийн панел дээр **Батлах/Татгалзах** товч — хүсэлтийг шууд шийднэ.

## 17. Google Maps — шинэ байршлыг зурагнаас нэмэх (v4.2)

Ажлын байр (талбай) нэмэхдээ координатыг гараар бичих шаардлагагүй — Google Maps-аас
сонгоно. Гурван арга зэрэг ажиллана:

| Арга | Юу хийх | Түлхүүр шаардлагатай юу |
|---|---|---|
| **1. Газрын зурагнаас сонгох** | Ажлын байр → «Шинэ ажлын байр» → **«Газрын зурагнаас сонгох»** → зурган дээр дарж/маркерыг чирж байршил сонгоно, радиусыг гулсуураар тааруулна → «Энэ байршлыг авах» | Тийм (Maps JavaScript API) |
| **2. Холбоосоос авах** | Google Maps дээр байршлаа олоод **Хуваалцах → Холбоос хуулах**; холбоосыг формд буулгаж **«Холбоосоос авах»** дарна | Үгүй |
| **3. Координат/миний байршил** | `47.9184, 106.9177` гэж бичих, эсвэл **«Миний байршил»** (GPS) товч | Үгүй |

### 17.1 Түлхүүр тохируулах (сонголтоор)
`Тохиргоо → Google Maps API түлхүүр` талбарт түлхүүрээ бичнэ. Google Cloud Console-д:
1. **Maps JavaScript API** — зурган дээр дарж сонгох, маркер чирэх;
2. **Geocoding API** — хайлтын талбар (хаяг/газрын нэрээр хайх).

Түлхүүрээ HTTP referrer-ээр хязгаарлахыг зөвлөнө. Түлхүүр **байхгүй ч** систем бүрэн
ажиллана: pickер нь зөвхөн харах горимтой (Google Maps embed, түлхүүр шаардахгүй) болж,
байршлыг 2, 3-р аргаар нэмнэ. Хадгалагдсан байршил бүрийг картан дээрх
**«Газрын зураг»** товчоор embed-ээр харж, «Google Maps дээр нээх» холбоосоор шалгана.

### 17.2 Холбоос задлах дүрэм (`POST /api/admin/geo/parse`)
| Хэлбэр | Жишээ |
|---|---|
| `@lat,lng,zoom` | `https://www.google.com/maps/@47.9184,106.9177,16z` |
| `!3d…!4d…` (place/data) | `…/data=!4m2!3d47.9184!4d106.9177` |
| `?q=`, `?query=`, `?ll=`, `?daddr=`, `?destination=`, `?center=` | `https://maps.google.com/?q=47.9184,106.9177` |
| Замын холбоос | `…/maps/dir/47.9184,106.9177/47.92,106.93` |
| Энгийн координат | `47.9184, 106.9177` |
| DMS | `47°55'06.2"N 106°55'03.7"E` |

Богино холбоос (`maps.app.goo.gl/…`) нь сүлжээгүйгээр задлагдахгүй тул систем
«Google Maps дээр нээгээд бүтэн холбоосыг хуулж тавина уу» гэж тодорхой зааварлана.
Буруу координат (өргөрөг > 90, уртраг > 180) хүлээн авахгүй.

## 18. Ажилтан БҮРИЙН гео хаалт — засах ба унтраах (v4.3)

Байгууллага бүхэлдээ нэг цэгт байдаггүй: жолооч талбай хооронд явдаг, гагнуурчин
шилжсэн цэг дээр ажилладаг. Тиймээс гео хаалт нь **ажилтан бүрд тус тусад нь**
тохируулагдана. Ерөнхий 300 м (эсвэл талбайн радиус) хэвээр — зөвхөн шаардлагатай
ажилтныг өөрчилнө.

| Горим | Утга | Хэзээ хэрэглэх |
|---|---|---|
| **Талбайгаа дагах** (`site`) | Оноосон ажлын байр, эсвэл үндсэн гео хаалт (анхдагч) | Байнгын ажилтан |
| **Өөрийн байршил** (`custom`) | `lat`, `lng` + өөрийн радиус (20–20 000 м) | Шилжсэн цэг, түр обьект |
| **Идэвхгүй / хаалтгүй** (`off`) | Байршил хязгаарлагдахгүй — хаанаас ч бүртгэнэ | Жолооч, хээрийн ажилтан |

### 18.1 Хаана засах вэ
* **Ажилтнууд** таб → мөр бүрийн **«Гео хаалт»** товч → горим сонгоод
  «Хадгалах». Цонх дотроос **«Газрын зурагнаас сонгох»** (Google Maps pickер),
  холбоос задлах, эсвэл GPS-ээр байршлаа авч болно.
* Мөн мөр дээрх **«Хаалтгүй болгох»** / **«Идэвхжүүлэх»** товчоор нэг даралтаар
  асаана/унтраана.
* **Ажлын байр** таб дахь «Ажилтны байршлын оноолт» хүснэгтэд ч мөн адил
  багана ба товчнууд байна.

### 18.2 API (v4.3)
| Зам | Тайлбар |
|---|---|
| `PUT /api/admin/employees/{eid}/geofence` | `{mode: site\|custom\|off, lat, lng, radius_m}` — горим, байршил, радиус |
| `GET /api/admin/employees` | Ажилтан бүрд `geofence: {source, mode, name, lat, lng, radius_m, enabled}` + `geofence_modes` |
| `GET /api/admin/employees/{eid}/geo` | Нэг ажилтны үйлчлэх хүрээ (горимыг харгалзана) |
| `GET /api/geo/check?lat=&lng=` | Ажилтан өөрийн горимоор шалгана (`mode`, `enabled`, `radius_m`) |
| `POST /api/agent/geofence-check` | `{latitude, longitude, employee_id` эсвэл `code}` — агентаас ажилтны горимоор |

Дүрэм: `off` горимд `enabled=false` ба «Энэ ажилтанд гео хаалт идэвхгүй — байршил
хязгаарлагдахгүй» гэж буцаана; `custom` горимд координатгүй бол, эсвэл радиус
20–20 000 м-ээс гадуур бол `400` алдаа буцаана. Гурав дахь хоногийн −10% торгууль,
хоцролт, шөнийн ээлж, чөлөө зэрэг бүх тооцоо хэвээр ажиллана.

## 19. Хэвлэх / PDF — хүснэгт бүрэн, цэвэр (v4.4)

Аль ч хүснэгтээ **«Хэвлэх / PDF»** товчоор (эсвэл `Ctrl/Cmd + P`) хэвлэхэд
зөвхөн өгөгдөл гарна: цэс, товч, огноо сонгогч, гүйлгэх хайрцаг бүгд арилж,
багана хуудаснаас халихгүй бүтэн багтана. Хөтчний «Save as PDF»-ээр PDF болгоно.

| Хэвлэх зүйл | Юу болдог |
|---|---|
| **Хуудасны толгой** | «Барилгын Бригад ХХК — Цалингийн тооцоо» + сар/огноо + хэвлэсэн цаг + хэвлэсэн хэрэглэгч (хүснэгт бүр дээр) |
| **Цэс, товч, мэдэгдэл** | Бүрэн нуугдана (`no-print`) |
| **Хүснэгт** | A4 хэвтээ; бүх багана харагдана, урт текст мөр дамжина, толгойн мөр хуудас бүр дээр давтагдана |
| **Өнгө** | Хэвлэгдэнэ (`print-color-adjust: exact`) — тасарсан/торгууль/чөлөө/шөнийн төлөв ялгагдана |
| **Мөр тасрах** | Мөр, карт, зураг дундаа тасрахгүй (`break-inside: avoid`) |
| **Цонхноос хэвлэх** | Цалингийн дэлгэрэнгүй цонх нээлттэй үед зөвхөн тэр цонхны агуулга хэвлэгдэнэ (хуудасны толгой харагдана) |
| **Ажилтны хуудас** | Ажилтан зөвхөн өөрийн цаг/цалингаа хэвлэнэ — бусдын нэр, дүн гарахгүй (нууцлал) |

Хэвлэх товч байрлал: толгой мөрд (одоогийн таб), **Цалин**, **Сарын тайлан**,
**Хүснэгт**, **Чөлөө**, **Ажлын байр**, **Ажилтнууд** таб болон цалингийн
дэлгэрэнгүй цонхонд.

### 19.1 Хүлээн авалтын шалгалт (v4.4)

## 20. Сард ХОЁР төлбөр — үндсэн цалин (10) ба аванс (25) — v4.5

Ажилтан сард **хоёр удаа** мөнгө авдаг: сарын **10-нд үндсэн цалин**, сарын
**25-нд аванс**.

| Төлбөр | Огноо | Хугацаа | Дүн | Нөхцөл |
|---|---|---|---|---|
| **1. Үндсэн цалин** | сар бүрийн **10** | өмнөх сарын **11 →** тухайн сарын **10** | ажилласан цалинг бүтнээр (нэмэлт цаг, цалинтай чөлөө нэмэгдэж, −10% торгууль хасагдаж, **25-ны аванс хасагдана**) | хүн бүр |
| **2. Аванс** | сар бүрийн **25** | **11 → 24** | **1 000 000₮** | зөвхөн 11–24-нд **7 хоногоос ДЭЭШ БҮТЭН өдөр** ажилласан бол |

Нэг өгүүлбэрээр: *«10-ны цалин 11 → 10 хугацааг тооцно; 25-ны аванс 11 → 24-нд
7 хоногоос дээш бүтэн өдөр ажилласан бол 1 сая төгрөг олгогдож, 10-ны цалингаас
1 сая хасагдана; ажиллаагүй бол 25-нд төлбөргүй, цалин бүхэлдээ 10-нд олгогдоно.»*

### 20.1 Бүтэн өдөр гэж юу вэ
* **Бүтэн өдөр** = тухайн ээлжийнхээ **90%-иас дээш**-ийг ажилласан
  (`full_day_min_credit = 0.9`). Өдрийн ээлж 09:00–19:00, шөнийн ээлж 19:00–03:00 —
  **шөнийн ээлж ч бүтэн өдөр** (хамгаалалтын 50% ч гэсэн).
* **Хагас өдөр** (жишээ нь 09:00–13:00, 4 цаг) авансын тооцоонд **орохгүй**.
* Демо өгөгдөлд `EMP012` яг **7** бүтэн өдөртэй → 25-нд **аванс авахгүй**;
  `EMP011` **11** бүтэн өдөртэй → аванс авах эрхтэй (хүлээгдэж байна).

### 20.2 Дүн ба хязгаар
* Авансын дүн `advance_amount = 1 000 000₮` (тохируулж болно).
* Аванс нь **11–24-нд ажилласан цалингаас хэтрэхгүй** (`advance_cap_earned = 1`):
  жишээ нь өдрийн цалин 50 000₮, 9 бүтэн өдөр → аванс 450 000₮.
* Аванс 10-ны цалингаас их бол 10-нд **0₮** олгогдож, хэтэрсэн дүн
  «Аванс цалингаас хэтэрсэн» гэж улаанаар тэмдэглэгдэнэ.

### 20.3 Админ: «Хоёр төлбөр» таб
| Хэсэг | Агуулга |
|---|---|
| **Үеийн сонголт** | Сүүлийн 6 үе (2026-10, 2026-09, …) — үе бүр «YYYY-MM» нэрээр, 10-ны огноотой |
| **25-ны аванс карт** | Олгосон (тоо, дүн) · Хүлээгдэж байна (дүн, эрхтэй тоо) · Авансын дүн ба нөхцөл |
| **10-ны үндсэн цалин карт** | Нийт цалин · Торгууль −10% · **Хасагдах аванс** · **10-нд олгох** |
| **Хүснэгт** | Ажилтан бүрээр: бүтэн өдөр (11–24) · аванс эрх · аванс төлөв (Олгосон/Хүлээгдэж байна/Олгоогүй/Цуцлагдсан) · аванс дүн · нийт цалин · торгууль · хасагдах аванс · **10-нд олгох** |
| **Үйлдэл** | 👁 дэлгэрэнгүй (бүтэн өдрүүдийн жагсаалт, цонхны цалин, шалтгаан) · ✓ **Аванс олгох** · ⊘ **Цуцлах** · ⟳ **Сэргээх** (цуцлагдсаныг буцааж «хүлээгдэж байна» болгох) |

Аванс олгоход/цуцлахад: ажилтанд «Аванс олгогдлоо — 1 000 000₮» мэдэгдэл,
админд мэдэгдэл, аудит бичлэг (`advance_paid` / `advance_cancelled`) үүснэ.
Хүснэгт бүхэлдээ **хэвлэгдэнэ** (v4.4 хэвлэлийн дүрэм) — `exports/10_two_payments.pdf`.

### 20.4 Ажилтан: «Миний цалингийн хуанли»
Ажилтны самбарт шинэ карт: **25-ны аванс** (төлөв, дүн, огноо),
**бүтэн өдөр (11–24)**, **10-ны үндсэн цалин**, **хасагдах** дүн, нөхцөлийн
тайлбар. Ажилтан зөвхөн **өөрийн** мэдээллийг харна (бусдын код, дүн гарахгүй).

## 21. Байршуулах — Render.com + GitHub (HTTPS-тэй, үнэгүй эхлэл)

Товч хувилбар: `deploy/DEPLOY_RENDER.md` (дэлгэрэнгүй, алхам алхмаар).

```bash
git init && git add . && git commit -m "attendance v4.5"
git remote add origin https://github.com/<НЭР>/attendance.git && git push -u origin main
```
→ <https://dashboard.render.com> → **New +** → **Blueprint** → repo сонгох → **Apply**
(`render.yaml` нь Docker + HTTPS + `/api/health` healthcheck-ийг бэлэн тохируулсан).

| Сэдэв | Товч |
|---|---|
| **HTTPS** | Render автоматаар өгнө — гар утсанд камер/GPS ажиллахад зайлшгүй |
| **PORT** | Render-ээс өгөгдөнө; `app.py` `PORT` env-ийг уншина (код өөрчлөхгүй) |
| **Free instance** | Түр зуурын диск: restart/deploy бүрд демо өгөгдөл шинээр үүснэ (туршилтад тохиромжтой) |
| **Бодит ашиглалт** | `plan: starter` + **Disk → mount `/app/data`** (сан + зураг хадгалагдана) |
| **Нөөц хуулбар** | `GET /api/admin/backup.zip` — админ эрхээр сан + бүх зургийг ZIP болгон татна |
| **Claude API** | Систем гадаад AI дууддаггүй — түлхүүр **шаардлагагүй**; AI агент холбох бол Render-ийн Secret env (`ANTHROPIC_API_KEY`), код/GitHub руу хэзээ ч бичихгүй |
| **Docker** | `docker compose up -d --build` · `deploy/install.sh` (Ubuntu) · `run.bat` (Windows) |
